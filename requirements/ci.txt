# CI test-environment pins — the SSOT for what the CI jobs install.
#
# WHY THIS FILE EXISTS (2026-09-20). The `test`, `virtual-fleet` and
# `falsifiability-drill` jobs each installed BARE PACKAGE NAMES, so pip
# resolved whatever was newest-compatible at the moment the job ran. The
# manifest-resolve job's own comment already named that hole for
# requirements/*.txt; nothing closed it for the jobs themselves.
#
# It is not theoretical. On 2026-09-20 commit cfad33b2 was green at 21:46
# and RED at 04:55 on the 3.9 leg with byte-identical code — re-running the
# green run unchanged reproduced the failure. The code was never the
# variable; the resolved dependency set was. (The latent test defect it
# exposed is fixed in d4cffeee; this file removes the trigger.)
#
# THREE consumers install these, so they share ONE constant — independent
# lists is exactly how this drifted (honest_failure_modes #5):
#   .github/workflows/ci.yml                  (test job)
#   .github/workflows/ci.yml                  (virtual-fleet job)
#   .github/workflows/falsifiability_drill.yml
#
# Versions are the set CI actually resolved on the GREEN run for
# d4cffeee (run 35492753180), read per-interpreter from that run's log —
# so by construction each pin is one this fleet has already passed on.
#
# ⚠️ SCOPE, stated honestly: these are the DIRECT dependencies. Transitive
# packages (bleak, dbus_fast, numpy, markdown_it_py, …) still float, and
# they differ sharply between interpreters — bleak resolved 1.1.1 on 3.9
# and 3.0.2 on 3.11 in that same green run. A full lock needs a per-Python
# constraints file generated by `pip freeze`, which the install steps now
# emit into the job log so one can be produced from a known-green run
# without scraping "Downloading" lines. This file narrows the surface; it
# does not eliminate drift, and saying otherwise would be the overclaim
# this repo's calibrated-claims rule exists to stop.
#
# ⚠️ Only bump a pin from a run that went GREEN, and say which run.

# --- formerly split by interpreter; single pins since 2026-09-20 -----
# These two carried python_version markers because the 3.9 CI leg could not
# install them: pytest 9.x and requests 2.34.x both need >=3.10. That leg is
# retired (support floor 3.9 -> 3.11, docs/fleet_platform.yaml), so ONE pin
# per package again -- honest_failure_modes #5's preferred shape.
#
# The 3.9 caps were not merely ugly. They held pytest at 8.4.2 (vulnerable
# under GHSA-6w46-j5rx-g56g, tmpdir handling) and requests at 2.32.5
# (CVE-2026-25645, insecure temp-file reuse in extract_zipped_paths), and
# BOTH are patched only in versions that need >=3.10 -- so while the floor
# stood, those two Dependabot alerts were unfixable by any bump. The choice
# was dismiss-as-tolerable-risk or retire the floor; retiring it fixes them
# by actually patching. Do not re-introduce a <3.10 marker here without
# re-opening that decision.
pytest==9.1.1
requests==2.34.2
