## ⚠️ How NOT to compute this (my first attempt, wrong)

I first harvested every SHA in the ledger and treated *"is an ancestor of some
ledger SHA"* as reviewed. That reported **8** unreviewed commits — off by an
order of magnitude, in the direction that falsely blesses code.

**Why it is wrong:** most ledger rows are **scope-limited**. Row 14 reviewed
`src/gateway/*` only; row 21 was the maps domain; row 13 is a named-commit
dude-claw diff. A commit touching `src/utils/` inside a gateway-scoped window
is an ancestor of that row's SHA but was never opened by it.

**Correct method:** only rows that explicitly reviewed a FULL window give
blanket coverage (they say so — *"the full unreviewed 37-commit window
`0a85896d..c17c611c`"*). Take the newest such row as the frontier; subtract
commits individually named by later scoped rows; everything else is unreviewed.

Both scripts are in this session's scratchpad pattern and trivial to rewrite;
the correct one is ~40 lines of `git rev-list` + `git show --numstat`.

## Findings already confirmed + FIXED this session (review these fixes)

**F1 — `probe_host_memory_pressure`: an unwritable state file silently and
permanently disables 2 of 3 legs.** `_save_hist_state` swallows `OSError` with
`logger.debug` (runner defaults to INFO → invisible); `_load_hist_state` maps
any read failure to `streak: 0`, so the streak can never reach
`debounce_ticks`, and `hist` stays empty so the RATE leg has no samples.
**Drill-proven**, 10 consecutive genuinely-degraded ticks:

```
state path unwritable:  0/10 fired
state path writable:    9/10 fired
wedge leg:              still fires
```

The module's own docstring calls the level legs *"the tombstone, not the
warning"* — the rate leg buys ~94 s vs ~4 s. So the failure reduces the probe
to the tombstone. Latent today (systemd `StateDirectory=meshforge` works), but
**Issue #60 is literally "sandbox path drift → writes silently fail while the
service stays active"**.

**F2 — same class, systemic.** `_load_parity_streak` returns `0` on any error
by design (*"favour silence on uncertainty, not a false page"*). Sound for ONE
uncertain read; it cannot distinguish "first sighting" from "I have been
unable to persist for three days." Five probe modules inherit it.

Cure pattern used for both is the repo's own **#63** (`delivery_counters`):
startup preflight that writes+reads a marker, a `consecutive_write_errors`
counter visible to a probe, and ERROR (not debug) on first failure.
